エージェントモードの Copilot は、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分を確認して変更ごとに採用または取り消し、追加のプロンプトで会話を方向付けられます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントに追加の指示を送り、高コントラストモードに加えてライトモードのトグルを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから、既定のテーマが暗すぎると感じる利用者向けのライトモードも必要だと依頼されました。新しい会話を始めずに、進行中のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が表示されます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. チャットをスクロールして、ツールの呼び出し、ファイルの読み取りと編集、実行を求められたターミナルコマンドを確認します。
3. ファイル編集が提案されたら、差分を確認します。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** を開き、セッション中にエージェントが変更したファイル全体を確認します。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止し **Allow** を表示します。内容を確認して、許可してよいコマンドだけを実行させてください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。変更をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに依頼する

高コントラストモードの作業が完了したら、同じ会話でライトモードのトグルも追加します。会話を続けることで、エージェントは変更済みのコンポーネント、スタイルの方針、設定をローカルストレージに保存する方法を引き継げます。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが既存の変更を調べ、ライトモードの追加を提案する様子を確認します。
3. 追加された各編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. 望まない方向に進んだ場合 (たとえば、トグルのユーザーインターフェイス (UI) を意図しない形で再構成しようとした場合) は、チャット入力欄の隣にある **Stop** で停止し、明確な追加プロンプトを送信します。

> [!TIP]
> セッション途中の方向付けは、最初からやり直すより短時間で済みます。追加プロンプトで調整を依頼できます (「Cascading Style Sheets (CSS) を簡潔にし、セレクターの重複ではなく CSS 変数を使う」など)。意図を伝え直すことも (「3つ目のトグルを追加せず、ライトモードを既存の設定パネルに組み込む」など)、範囲を広げることもできます (「両方のトグルにキーボードショートカットも追加する」など)。

## 作業セットをレビューする

コミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更ファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンである Accessible Rich Internet Applications (ARIA) 属性、キーボードナビゲーション、セマンティック HyperText Markup Language (HTML)、ローカルストレージへの保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。
